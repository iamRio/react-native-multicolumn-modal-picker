# Contributing

Thanks for helping improve `react-native-multicolumn-modal-picker`. Bug reports,
reproduction examples, documentation fixes, and focused code changes are
welcome.

Please follow the project's [Code of Conduct](CODE_OF_CONDUCT.md). For
security vulnerabilities, use one of the private reporting channels listed in
[SECURITY.md](SECURITY.md) instead of opening a public issue.

## Before opening a pull request

- For a bug, check existing [issues](https://github.com/iamRio/react-native-multicolumn-modal-picker/issues)
  and [discussions](https://github.com/iamRio/react-native-multicolumn-modal-picker/discussions)
  first. Include the package version, React Native version, platform (Android,
  iOS, or Web), relevant peer dependency versions, expected and actual
  behavior, and a minimal reproduction when possible.
- For a larger change or a new feature, open a discussion or issue first so the
  proposed behavior can be agreed on before implementation.
- Keep changes focused. Preserve the existing public API and cross-platform
  behavior unless the issue explicitly calls for a change.

## Local development

Use the Node.js version specified by the repository's `.nvmrc` when using
nvm. Install the locked development dependencies with:

```bash
npm ci
```

The package is written in TypeScript. Implement runtime changes under `src/`
and add or update focused Jest tests under `tests/`. Update the README when a
change affects the public API, supported platforms, installation, or user
visible behavior.

`npm ci` is sufficient to run `npm run validate`, as in CI. It installs
`@react-native-picker/picker` from the development dependencies. The Jest suite
tests platform-specific component logic, including Web behavior, but does not
run native iOS/Android builds or render through `react-native-web`. For an
integration check in a Web app, install the optional `react-dom` and
`react-native-web` peer dependencies as described in the README. To build an
iOS app, install the optional `@react-native-picker/picker` peer dependency in
the consuming app and use its native build tooling.

## Validation

Before submitting, run the full project validation:

```bash
npm run validate
```

This runs the formatting check, TypeScript checks, lint, Knip, and the Jest
coverage suite. The coverage suite enforces 100% statements, branches,
functions, and lines for executable code under `src/`.

If you change packaging or want to verify the generated package, build it and
inspect the package contents:

```bash
npm run build
npm pack --dry-run
```

`dist/` is generated by the build; do not commit generated output unless a
maintainer specifically requests it.

## Pull requests

- Describe the problem and the intended change. Link the related issue or
  discussion when there is one.
- Summarize the checks you ran and their results. If a check cannot be run,
  explain why.
- Include screenshots or a short recording when a user-facing visual change
  benefits from them.
- Keep unrelated formatting, dependency, and generated-file changes out of the
  pull request.
- Change `package-lock.json` only when the pull request intentionally changes
  dependencies. Regenerate it with npm so it stays in sync with
  `package.json`; do not include unrelated lockfile changes.
- Do not change the package version or publish a release as part of a
  contribution unless a maintainer asks you to.
